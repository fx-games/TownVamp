# Agent notes

## LDtk MCP server (`ldtk`)

Edits `files/assets/maps.ldtk` (LDtk JSON v1.5.3) directly. Registered in
[.mcp.json](.mcp.json); binary built from https://github.com/gazure/ldtk-mcp at
`/Users/felix/Projects/ldtk-mcp/target/release/ldtk-mcp` (rebuild: `cargo build --release`).
Needs a session restart to appear.

### Workflow

`open_project` (path `files/assets/maps.ldtk`) → `describe_defs` → read/edit → `validate_project`
→ `save_project`. Edits stay in memory until `save_project`. LDtk GUI must reload the file after.

### This project's map

- One world, `Free` layout, one level: `Town` (576×320 px = 72×40 tiles, at world -912,-1104),
  no external levels.
- Layers: `Meta` (Entities), `Entities` (Entities), `Tiles` (Tiles). **No IntGrid and no AutoLayer**
  — so `set_intgrid` / `flood_fill_intgrid` do not apply; tiles are painted directly with
  `paint_tiles` / `clear_tiles`.
- Tileset `World` = `classic_roguelike.png`, 8×8 tiles. Grid size 8 everywhere; entity grid
  coordinates are 8 px cells.
- Entity defs and fields:
  - `NPC` (tag NPC) — `Name`, `InternalName`, `UniqueName`, `ASCII` (String), `Tile` (Tile),
    `Type` (enum `NPCCategory`), `FlipLookDirection` (Bool). NPCs live on the `Entities` layer.
  - `Location` (tag META) — `Name`. On the `Meta` layer.
  - `Sign` (tag OBJECT) — `Text`. `Shrine`, `Door` (tag OBJECT) — no fields.
- Enums: `NPCCategory`, `TilesetMeta` (IsBlockingMovement / IsBlockingView / IsWater / IsDamaging),
  `TemplateAreas`.

### Tile ids and names

Tile id = `row * 28 + col` (tileset is 28×28 tiles = 784, 8 px each). Names for ~200 ids already
exist as Go constants in [defs/definedIcons.go](defs/definedIcons.go) — reuse those names, they are
what the game code refers to. Blocking behaviour is not in the name: it comes from the tileset's
`enumTags` in the `.ldtk` (`IsBlockingMovement`, `IsBlockingView`, `IsWater`, `IsDamaging`), so
check the tag before painting something as a wall.

The whole Tiles layer is generated by [scripts/build_town.py](scripts/build_town.py) — the layout
from [docs/specs/town-design-handover.md](docs/specs/town-design-handover.md) as rectangles, plus a
flood fill from the lair that asserts every named place can be walked to. Edit the layout there and
re-run it; it rewrites only `gridTiles` and the level size, so entities survive. Do not hand-paint
the tile layer over it, and run it *after* any MCP `save_project`, never before.

**Windows (763, 764) are the only tiles that block movement without blocking view.** That
asymmetry is the point of them: a Private Action performed indoors can be watched from a street the
performer cannot reach. Tagging them `IsBlockingView` as well would make them ordinary walls and
quietly remove the one way into a lit room. [scripts/build_town.py](scripts/build_town.py) puts them
in every building's outer walls and asserts at the end that none was painted over.

Tiles 728–753, 761–764 are the town props drawn for this PoC (anvil, waterwheel, fence, chair,
bucket, bell, windows, …) — see [docs/tileset-coverage.md](docs/tileset-coverage.md) for the full list and
what the tileset can depict. The art itself is ASCII in
[scripts/add_sprites.py](scripts/add_sprites.py); edit it there and re-run rather than painting
into the PNG by hand.

To look at a map after editing it:

```bash
python3 scripts/render_ldtk.py /tmp/town.png
```

### Named locations

`Location` entities on the `Meta` layer are how the data files address the map: routines in
`files/assets/data/townspeople.rec` and `at:` in `obligations.rec` take either `x,y` or one of these
names, and `spawn` is both the player's start and the vampire's lair
([game/vampire.go:136](game/vampire.go:136)). Prefer names — coordinates rot the moment the layout
moves.

Currently: `spawn`, `town_square`, `main_road`, `inn`, `inn_cellar`, `innkeeper_bedroom`,
`blacksmith`, `smith_storage`, `blacksmith_bedroom`, `carpenter_workshop`, `carpenter_interior`,
`carpenter_bedroom`, `church`, `priest_study`, `priest_bedroom`, `cemetery`, `childs_grave`,
`farmhouse`, `farmer_bedroom`, `barn`, `vegetable_field`, `grain_field`, `lunch_tree`, `mill`,
`mill_interior`, `miller_bedroom`, `river`, `bridge`, `quiet_riverbank`.

Zone rectangles in `zones.rec` are still raw `x,y,w,h` against this layout, so moving a building
means moving its zone too.

### Gotchas

- The Go side loads this file at `assets/maps.ldtk` ([main.go:147](main.go:147), and
  [game/harness_test.go:34](game/harness_test.go:34)) — a broken save breaks the game and the tests.
  Run `go test ./game/...` after structural edits.
- LDtk writes its own backups to `files/assets/maps/backups/`; those are LDtk's, not a safety net
  for MCP edits. `maps.ldtk` is git-tracked — check `git diff` before committing a generated edit.
